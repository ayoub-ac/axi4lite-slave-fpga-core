# Synthesis comparison report

Generated by `make synth_report`. Numbers are post-synthesis, pre-place-and-route.
Vendor flows (Vivado / Quartus) usually pack tighter than the open-source flow,
so the Yosys numbers should be read as upper bounds.

## Notes

* AXI4-Lite slaves are small. The dominant area is the register file
  itself (NUM_REGS x DATA_WIDTH FFs) plus the AW/W/B/AR/R handshake
  state machine (~50 FFs of slave-side state). For the example top
  (16 x 32-bit registers, 1 RC, 1 W1C, 2 RO) expect roughly 200-500
  LUT and 600-700 FF on iCE40 / ECP5 / Artix-7 generic synthesis. Vendor
  packers reduce this further because the byte-strobe write logic and
  the read mux fold into LUT6 / SLICEM cells nicely.
* The address-decode path is a single comparator against NUM_REGS plus
  alignment bits — a couple of LUTs each. DECERR detection adds nothing
  on the critical path; it lives in the same combinational block.
* No BRAM is required: the register file is implemented as discrete
  flip-flops so the values are visible on `reg_storage_o` for the
  user logic. A BRAM-mapped variant for very-wide register banks
  (NUM_REGS > 256) is on the Premium roadmap.
* Vivado / Quartus rows are skipped automatically when those tools are
  not on PATH; on a CI runner with WebPACK / Web Edition installed they
  will be populated from a real synth_design / quartus_sh run.

## Reproduction

```
make synth_report
```
